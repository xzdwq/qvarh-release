# Qvarh Release Builder

Расширение VS Code для сборки релизной ветки из локальных git-веток: выбираете ветки, смотрите объединённую хронологию коммитов, проверяете конфликты dry-run'ом и собираете релиз через cherry-pick. Работает только с локальным git — без API таск-трекера или Bitbucket, ссылки на задачу/PR/коммит собираются по URL-шаблону.

## Возможности

- **Список веток** — локальные и remote-tracking, фильтр по имени/задаче, дата и автор последнего коммита, бейджи "уже в main" / "частично в main".
- **Хронология** — коммиты выбранных веток (относительно dev-ветки) в одном списке по времени, с цветной дорожкой веток и точками слияния в dev.
- **Проверка конфликтов** — реальный dry-run cherry-pick во временном worktree, с подсказкой вероятной причины конфликта.
- **Забытые ветки** — отдельно показывает старые ветки, которые ещё не влиты в dev и не попали в текущую хронологию.
- **Сборка релиза** — создание ветки и применение плана автоматически или по шагам, с возможностью исключать коммиты.
- **Профили проектов** — настройки на каждый репозиторий отдельно, можно собирать релиз для любого из них без переключения открытого workspace.

## Настройка

Всё в боковой панели (иконка на Activity Bar) → "Проекты". На каждый репозиторий:

- **Основная ветка** и **dev-ветка** — от какой создаётся релиз и от какой считаются "свои" коммиты ветки.
- **Remote**, шаблон релизной ветки, префиксы служебных веток (`qa`, `chore/` и т.п.).
- Базовый URL таск-трекера, workspace/repo slug Bitbucket — для ссылок на задачу, PR и коммиты.

Лимит показа веток задаётся прямо в панели сборки, рядом с фильтром.

## Использование

1. Добавьте проект в боковой панели или откройте репозиторий как workspace и запустите команду `Qvarh Release: собрать релизную ветку`.
2. Откройте панель нужного проекта, при необходимости — Pull нужной ветки.
3. Отметьте ветки для релиза → "Построить хронологию" (конфликты проверяются автоматически).
4. Проверьте бейджи и подсказки по конфликтам, укажите дату релиза → "Создать релизную ветку".
5. Примените план автоматически или по шагам; при конфликте — разрешите его и продолжите.

Прерванную сборку продолжает команда `Qvarh Release: продолжить сборку релиза` — для текущего открытого workspace.

## Известные ограничения

- Слияние ветки в dev определяется по топологии (сам merge-коммит в `--first-parent` истории dev, а не по тексту subject) — работает независимо от хостинга и языка сообщения. Номер PR — best-effort парсинг subject, может не определиться (тогда просто нет ссылки на PR). Squash-merge (без отдельного merge-коммита) дорожка не распознаёт как влитую — там нет самой точки топологии, которую можно было бы найти.
- Поиск причины конфликта и "забытых" веток — эвристика по файлам/patch-id, не по смыслу изменений.
- На ветку берётся не более 300 коммитов относительно dev; список веток по умолчанию показывает 100 самых свежих (настраивается).
- Конфликты cherry-pick разрешаются вручную в редакторе — расширение только останавливается и ждёт.

## Если ветка не переключается

Скорее всего где-то остался незавершённый cherry-pick. В панели есть кнопка **Отменить сборку (cherry-pick --abort)**, либо вручную: `git cherry-pick --abort` и `git worktree prune`.

## Установка

**Режим разработки (F5):** открыть папку проекта в VS Code, нажать `F5` — откроется Extension Development Host с расширением. `npm run watch` в фоне пересобирает `dist/extension.js` при каждом изменении — окно всё равно нужно перезагрузить (`Ctrl+Shift+F5`).

**Как обычное расширение (.vsix):**

```
npm run package
code --install-extension qvarh-release-<версия>.vsix
```

## Разработка

- TypeScript, esbuild собирает `src/extension.ts` в один `dist/extension.js` (`npm run compile` — разово, `npm run watch` — в фоне). `vscode` — внешняя зависимость, не бандлится.
- HTML/CSS/JS панелей (`src/ui/releasePanel.ts`, `src/ui/settingsView.ts`) — один большой TS-темплейт-литерал на файл, а не отдельные `.html`/`.js`. Внутри `<script>` символы `` ` `` и `${...}` экранируются (`` \` ``, `\${`), иначе TS примет их за часть внешнего темплейта.
- Тестов и линтера нет — проверка через `tsc --noEmit` и ручную проверку в Extension Development Host.
